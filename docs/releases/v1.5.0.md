# TaskFlow v1.5.0 — release notes draft

**Unpublished release candidate.** The preparation PR targets develop. No v1.5.0
tag, GitHub release, staging promotion, or production deployment is performed in
this phase. Publishing and production verification remain #91; #34 and #3 stay open.

## Summary

TaskFlow v1.5 improves maintainability, reliability, accessibility and testing of
the existing four-stage workflow board. It preserves the application's visual
identity and is not a major redesign.

## Improvements

- Strict TypeScript/domain validation, deterministic reducer operations and
  explicit action ownership protect tasks from failed movement and stale edits.
- Linked subtasks are independent tasks with their own workflow stage. Parent
  progress is derived from the full board; completion requires every subtask Done.
  One hierarchy level is supported. Detachment/reassignment preserve work;
  confirmed parent deletion keeps subtasks as independent tasks.
- Runtime validation and schema-2 persistence replace unchecked JSON hydration.
  Unversioned and v1 checklists migrate to linked tasks with stable identities.
  Invalid/future data and failed migrations preserve the saved original; failed
  writes retain memory and expose retry. External tab changes pause saving until
  a confirmed reload rather than silently merging or overwriting stale work.
- Named dialogs, associated validation errors, focus containment/restoration,
  keyboard movement announcements and reduced-motion support improve interaction.
- Typed success, error, warning and information notifications have consistent
  replacement/dismissal behavior. Actionable warnings and errors remain visible.
- Responsive card, filter, parent-context and dialog fixes retain usable controls
  at narrow/short viewports. Touch hold-and-drag and bounded board dragging are
  supported alongside keyboard movement.
- Component-owned CSS and explicit shared styles replace duplicated App.css rules.
- Unit/component/integration coverage and six desktop/mobile Chromium smoke cases
  run with lint, strict TypeScript and build in GitHub Actions. CI keeps the
  established required job names and reports browser failure artifacts.

## Upgrade and compatibility

The `taskflow-board` LocalStorage key stores schema **2**, distinct from the
application release version **1.5.0**. Supported migration paths are unversioned
v0 → v1 → v2 and explicit v1 → v2. Valid current-v2 data loads without rewriting.
Checklist IDs/titles are preserved; completed items become Done, incomplete items
To Do, with parent priority/category, empty description and parent creation time.
Invalid identities/relationships reject the whole conversion. Reloads do not
repeat conversion or duplicate subtasks. No separate backup key is created.

Only genuinely missing storage initializes the sample board. Invalid/future data
opens an empty workspace with saving paused and the original untouched. Keep the
tab open when saving fails; Retry saving or confirmed Reload saved board are the
supported recovery actions. See [persistence compatibility](../v1.5-persistence-reliability.md).

Data is local to a browser/profile and exact origin. Preview, staging, production
and different localhost ports do not transfer boards. There is no automatic merge
or transactional multi-tab guarantee. Done tasks cannot reopen; workflow remains
forward one stage at a time. See [parent/subtask rules](../v1.5-parent-child-tasks.md).

## Verification and known limitations

[Release QA](../v1.5-release-qa.md) records current results and pending checks;
[scope inventory](../v1.5-release-scope.md) maps issues to merged source. Historical
[#53 measurements](../v1.5-quality-baseline.md) include Chrome/Safari, seven sizes,
native 200% zoom, Lighthouse medians, and owner VoiceOver review in Google Chrome.
They do not substitute for exact release-preview QA.

The identified small-text contrast and development-tool dependency findings
were resolved in PR #138; fresh corrected-preview and VoiceOver verification
remain pending. Other findings include missing meta description and
local-preview robots/Speed Insights behavior requiring deployed-origin review.
Full WCAG compliance and release readiness are not claimed. No new application
features are included in this preparation branch. PR #138 contributes focused CSS
fixes, removal of unused deployment tooling and three transitive patch updates.

## Deferred work

Capacity/WIP policy, manual ordering, major board/detail redesign, design tokens,
large-board performance planning and stronger persistence belong to approved
v2.0 planning. Due dates, import/export, authentication, backend/cloud storage,
teams/collaboration, AI, analytics/audit/history logs, assignees and notes are not
v1.5 features and are not implicitly approved by this release note.
