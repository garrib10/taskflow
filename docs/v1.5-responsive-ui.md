## Confirmed defects and decisions

- At 320px, the column's retained 320px minimum exceeded its 288px padded board.
  An unbroken description made the page 1722px wide in the stress fixture.
  Mobile columns now have a zero minimum width. Descriptions and titles wrap
  within cards; horizontal overflow is contained by the existing board scroller
  above the mobile stacking breakpoint.
- Mobile search inherited a 420px flex basis as its height when controls changed
  to a column. It now uses an automatic basis, reducing the tested search block
  from 420px to approximately 76px, without shrinking its text or input.
- Badges exceeded their allocated flex space beside Edit/Delete. Priority/category badges stay together; the footer wraps the action group
  when both groups do not fit on one row. All existing task controls remain present, with 44px action
  targets. Card titles retain their full text; the mobile heading clipping rule
  was removed so it cannot clip the title button's focus outline.
- Long parent names overflowed confirmation messages (821px beyond the dialog's
  content width at 320px). Confirmation text and labels now wrap. Both task and
  confirmation panels have viewport height limits and internal vertical scrolling.
  A `vh` fallback precedes `dvh`; width uses the padded overlay rather than `vw`.
  Actions remain inside the form/dialog and stack on narrow screens.
- A long subtask title could exceed the editor's 200px nested scroller and clip
  its focus indicator. The form now owns scrolling, with padded list rows and no
  nested list height limit. Many subtasks increase editor scroll length, while
  the board card still displays only its compact segmented progress indicator.
- Long parent pill titles stay on one line with ellipsis, with their complete
  accessible name and tooltip preserved. The icon and `Parent:` label do not shrink. Existing blue
  styling, hover actions, child ordering and completion indicators are preserved.
- The desktop/tablet board remains horizontally scrollable where four columns
  do not fit. A visible hint appears at the relevant widths. Its named Workflow
  columns region has a tab stop for native arrow-key scrolling. Drag handles and
  task buttons keep their existing names, keyboard bindings and focus behavior.
- Notification messages already wrapped correctly. Dismiss controls now have
  44px targets. Long warnings and storage recovery controls remain in document
  flow and can be reached by scrolling; they do not overlay core controls.
- Confirmation entrance animation and card/control hover motion ignored reduced
  motion. Owning stylesheets now remove those effects. Notification animation
  already respected the preference. Keyboard drag scrolling remains immediate;
  pointer drag position feedback remains functional.

There is no new keyboard detection JavaScript, fixed dialog content height,
page-level overflow masking, CSS framework, navigation shell or card redesign.
The existing component-specific stylesheet ownership remains intact.

   descriptions, inspect badges/actions, and search/filter/reset.

   retained incorrect height. Include Safari if available.
6. Enable the OS reduced-motion preference and verify immediate hover/drag/status
   feedback, notification dismissal and confirmation opening.

Long task content intentionally increases card and editor scroll length rather
than shrinking text or hiding controls. The parent context pill abbreviates only
its title visually; its full accessible name, tooltip and parent editor remain available. Larger action targets can put actions on a
second row in narrow cards. These are reviewable layout tradeoffs. Broader mobile
navigation, visual redesign and new task features remain deferred to v2.0.

## Drag boundary review — October 6

Owner reduced-motion review found that a task dragged past Done could scroll all
columns off-screen. Native pointer reproduction expanded a 1440px desktop board's
scroll width from 1408px to 4237px, with scrollLeft reaching 2597px. On mobile,
the page expanded from 375px to 3138px while dragging.

A dnd-kit modifier now constrains the card to the combined current bounds of the
actual column elements, rather than using scrollWidth, which includes the dragged
card and was growing with each auto-scroll. The constraint applies to the drag
collision geometry as well as its visual position. Column positions are measured
in their current scrolled locations, allowing normal scrolling to off-screen
columns. Mobile movement between stacked columns remains available. No dependency
was added and no workflow or persistence rule changed.

Pointer checks at 1440, 1024, 768 and 375px passed with reduced motion and ordinary
motion. Board widths stayed at their original 1408, 1328, 1328 and 343px; page
widths stayed equal to viewport widths. Desktop/tablet pointer drops into Done
still succeeded. Sixteen native keyboard checks passed across desktop, tablet,
mobile and actual 200% Chrome zoom: repeated last-column keys, forward drops,
rejected reverse drops, Escape cancellation, restored focus and bounded scrolling.

Five focused tests cover normal transforms, both outer edges, scrolled column
bounds, stacked mobile geometry, preserved scale feedback and missing measurements.
Final full verification: 284 tests / 22 files passed in 22.50 seconds; typecheck,
lint, production build and whitespace checks passed. Detailed before/after browser
measurements are in [drag boundary evidence](v1.5-drag-boundary-evidence.json).

Owner retest: drag an In Review task toward and beyond Done, pause at the far edge,
and release. The board should stop at its real final column; columns must not be

when workflow and parent completion rules permit it.
