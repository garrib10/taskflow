`a9f53e7000c7a900566723aa492d17e1e971768c`, after merged PR #136. The working branch
is `release/v1.5.0-prep`. Application source is unchanged; only release metadata,
documentation and portfolio screenshots change. This report is completed with
exact evidence before the draft PR is finalized.

## Returning-user and multiple-tab local evidence

Controlled fixtures covered both unversioned v0 (with missing In Review column)
and explicit schema-v1 boards, each with one parent and two checklist items.

- First use initialized the valid nine-task/four-column sample board and schema 2.
- Both legacy formats restored required columns and migrated to exactly three
  linked task records. Parent content/status/metadata remained intact; entry IDs,
  titles, parent link, inherited priority/category and creation time matched the
  documented defaults; descriptions were empty, completed→Done, unfinished→To Do.
- Two subsequent reloads preserved identical stored bytes/revision and identities;
  no repeated conversion, duplicate, task loss or orphan occurred.
- Migrated tasks remained editable and persistable. The editor requires a
  description; one was supplied when editing a migrated empty-description task.
- Corrupt JSON, invalid legacy priority, a completed parent with unfinished legacy
  work, and schema 99 all opened an empty saving-paused workspace. Memory edits
  worked; the original remained byte-for-byte unchanged across edits and reload.
- Child deletion removed only that child. Cancelled parent deletion preserved all
  records; confirmed **Delete Parent and Detach Subtasks** retained the surviving
  child as independent, including after reload.
- UI created two subtasks from a parent editor; parent edits and reload preserved
  both links and completed/total progress.
- High/Medium/Low ordering and stable equal-priority creation order passed;
  description search and Reset passed.
- Native same-origin two-tab edits paused stale saves, retained local memory,
  showed accurate warning feedback, and blocked stale writes. Cancelled reload
  retained local work; confirmed reload adopted the saved external board. Exactly
  one storage event was observed and bytes remained stable afterward, with no
  write/notification loop during the observation window.

The local complete journeys also verified parent completion blocked with a hidden
unfinished subtask, then succeeded after subtask completion; independently moved
subtasks; ordinary CRUD; field errors; notifications; unsaved confirmations; and
keyboard dismissal/restoration. Domain edge cases and save-failure/retry are
covered by the automated suite; no transactional multiwriter guarantee is claimed.
