## Cascade and safe cleanup

CSS module traversal in Vite can reorder otherwise equal-specificity rules. Each owner's rules retain their original relative order, including base-before-media overrides at 1024px and 600px. Shared edit-button styles load before the editor's equal-specificity `.add-editor-subtask` padding override. `.relationship-link` stays before `.subtask-title`; editor parent-pill focus and notification dismiss focus retain their specificity. Generic focus stays global; component input focus and specialized focus continue to override it as before. No cascade layers or selector renames are used.

The audit confirmed four identical repeated modal blocks: `.create-task-modal`, `.create-task-modal form`, `.create-task-modal textarea`, and `.create-task-actions`. A fifth repeated input/textarea/select block repeats the base declarations but omits the earlier transition; cleanup must retain that transition. No intervening declaration changes these values. Consolidation keeps the first complete rules.

`.subtask-completed` is obsolete: SubtaskItem emits `.completed`, no runtime construction uses `.subtask-completed`, and no tests reference it. Removing the dead selector preserves the existing appearance. Changing the rendered completed checklist appearance belongs in separate visual work.

Other safe deletions: the mobile board-container padding repeats its unconditional padding; three mobile task-footer declarations repeat its base display/alignment/margin; task-form-field label weight and select width are already supplied by the higher-specificity shared dialog selectors, and these fields are rendered only inside that dialog. Both 600px TaskForm media blocks are consolidated after their independent base selectors. No effective values change.

Keep all dynamic priority border/badge and category classes from the domain style records; success/error and danger/primary variants; `.is-complete` on progress, task status, parent icons, and child icons. Keep the legacy input/delete/add controls and empty state, although normal board usage disables legacy creation: they remain part of SubtaskList's supported render paths. Keep scrollbar pseudo-elements and mobile WebKit line-clamping. The baseline contains no reduced-motion override; this refactor preserves that existing behavior rather than adding an accessibility feature.

## Deferred findings

- The unused legacy completion selector did not match rendered markup before this change. Its removal is cleanup; introducing strikethrough/color would change visual behavior. Parent #40's matching completion-style requirement therefore needs a separately agreed visual fix.
- Reduced-motion handling is absent on develop. Existing transitions/animations are retained; add appropriate handling in the accessibility work.
- At 375px the search area's existing 420px flex basis becomes vertical space when board controls switch to a column, leaving a tall search panel. Both builds reproduce it; responsive issue #31 should address it separately.
- This refactor does not claim to complete keyboard focus restoration, focus trapping, screen-reader announcements, responsive polish, or the v2.0 redesign.
