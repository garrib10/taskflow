# TaskFlow v1.5 integration and production quality

## Baseline and audit

Started from clean `develop` at `a9ffc820d9c3760774cfaddaa6a6a266c2b5bf32`, matching
origin and containing merged PR #134, typed notifications, accessibility, linked
tasks, validated persistence/migrations, and component styles. `npm install`
was up to date (277 packages) and did not change the lockfile. Baseline: **289 tests
in 23 files, 22.94 s**; typecheck, lint and build passed. Build: 64 modules, 366 ms,
CSS 20.71 kB / gzip 4.48, JS 280.05 kB / gzip 87.14. Only after this baseline was
`test/v1.5-integration-ci` created and published.

Vitest merges the existing Vite config, uses jsdom, two workers, explicit APIs,
jest-dom matchers and per-test cleanup. Existing fixtures build typed boards and
tasks. Storage tests mock/inject only the browser storage boundary. Board tests
already exercise reducer-backed UI journeys, keyboard/touch sensors and error
feedback; App notification tests already cover migration, corrupt/future storage,
write failure/retry and external-tab conflicts. No browser framework existed.

The remaining gap was journeys through the complete App: CRUD → movement →
restoration → deletion; filtering without persistence mutation; a multi-child
family through edits, completion and reload; deletion/detachment with persisted
relationships. Pixel measurements, native focus, and deployed browser behavior
require a real browser rather than jsdom.

## Test pyramid and scope

- Domain unit tests protect exhaustive rules, atomic reducer validation, migration
  shapes, cycles, unsupported depth and duplicate IDs. Those assertions are retained.
- Component and hook tests protect forms, typed notices, focus and browser boundary
  failures. Existing full-App storage failure tests are reused rather than copied.
- Five new full-App journeys integrate UI, real sensors, reducer and LocalStorage.
  Only jsdom geometry is stubbed for movement. Controlled boards use fixed fixture
  dates; generated IDs are observed rather than assumed. Storage and spies reset.
- Three browser journeys run in two Chromium projects (six cases): lifecycle and
  keyboard warning dismissal, parent context/persistence, keyboard dialogs and
  narrow controls/overflow. Every test receives an independent browser context.
  No personal data, credentials, snapshots, fixed sleeps or retries are used.
  Page exceptions and failed core JS/CSS responses fail the browser cases.

Chromium at 1280×720 and 390×844 keeps CI small and checks the actual responsive
layout and native keyboard sensors. Keyboard movement avoids timing-sensitive
pointer dragging and is already a supported accessible interaction. Existing real
mouse/touch sensor tests and owner physical-phone review from #134 remain relevant;
this package does not claim Safari, Firefox, physical-device or spoken screen-reader
coverage. Playwright starts Vite on 127.0.0.1:4173 locally and in CI. An optional
`PLAYWRIGHT_BASE_URL` runs the same suite against an accessible deployed origin.
Failure-only screenshots/traces, reports and outputs stay out of Git.

## Integration behavior protected

`App.journeys.test.tsx` creates from first use, edits all four permitted fields,
moves forward, remounts, rejects reverse movement twice with dismissal between
attempts, and confirms deletion. The second journey searches title/description,
checks individual and combined priority/category/status filters, resets, and
asserts the persisted board never changes during filtering.

`App.relationships.test.tsx` creates a parent and two linked children through the
editor, edits child and parent without losing links, moves the parent into review,
hides children by search, checks blocked completion against the full board,
completes both children, completes the parent, rejects reopening, and remounts.
Relationship management excludes self-parent, unsupported depth and unfinished
assignment to completed parents; valid reassignment preserves task identities.
The UI does not offer invalid circular links. Exhaustive rejected-action/no-mutation
checks remain in `boardReducer.test.ts` and `taskRelationships.test.ts`.
Deletion checks child removal, cancelled parent deletion, confirmed detachment,
focus on the surviving task, persisted identities, and remount without an orphan.

Existing `App.notifications.test.tsx` protects valid legacy migration and its quiet
second load without duplication, corrupt/future-version recovery without overwrite,
failed writes without false success and successful retry, plus external-tab conflict
feedback. Existing `App.accessibility.test.tsx` protects recovery confirmation
focus, trapping and cancellation. These are part of the integrated release gate.

## CI and branch expectations

The existing Frontend CI workflow is extended, not duplicated. One Node 24 job
uses cached npm downloads and `npm ci`; it runs lint, strict typecheck, all Vitest
tests, build, Chromium installation with Linux dependencies and six browser cases.
Its 20-minute timeout includes browser installation. Failure evidence is retained
for seven days. Contents read is the only workflow permission, checkout credentials
are not persisted, and no secrets or privileged pull_request_target event is used.

The public active ruleset was inspected on October 7, 2026. develop/staging/main
are protected; required check names are **Lint and build** and **Dependency review**.
The former name is deliberately retained, so its new test failures block merging
without requiring a new unavailable status. CodeQL and Vercel statuses remain
visible review evidence; this PR does not change repository rules or promotion.
Push triggers now also validate develop/staging/main. The public solo repository
needs no paid environment, large browser matrix, coverage service or parallel
install jobs. Browser download is the principal added CI cost; one CI worker
bounds memory and logs remain actionable. No Lighthouse-on-every-PR gate is added.

## Dependency advisories and release limitations

braces, fast-glob, gh-pages, globby, micromatch, nanoid and source-map-js. None are
Playwright packages. The existing optional fsevents install-script warning remains.
No unrelated audit fix or deployment-tool removal is included. Review existing
advisories before release; remediation belongs in a focused dependency change.

Full updated Lighthouse comparison against the Day 1 baseline, broader browser
and returning-user release regression, release documentation and staging/main
